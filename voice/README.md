# Голосовые эксперименты (не заработали)

Здесь лежат попытки сделать голосовое управление плеером **без облака Алисы**: чтобы фраза
распознавалась на самой колонке. Все они доведены до конкретного места, где упираются в
прошивку. Файлы оставлены, чтобы не повторять путь заново.

## Что получилось выяснить

- **Штатные библиотеки споттера грузятся из своего бинарника.** `libyandex_evil.so`,
  `libtflite.so`, `libiconv.so` открываются через `dlopen`, модели из
  `/system/vendor/quasar/spotter_models/` читаются, кадры по 20 мс принимаются.
  Сборка: `zig cc -target arm-linux-gnueabihf.2.30 -mcpu=cortex_a7`.
- **Модель активации требует один канал:** `spotter_create` с нулём каналов падает с
  `channel count doesn't match (1 in spotter conf, 0 in api call)`. Это сообщение есть и в
  журнале штатного запуска Алисы — само по себе оно безобидно.
- **Слова-активаторы локальны:** модели `alisa`, `yandex`, `yasmina` считаются на устройстве,
  в облако уходит только звук после срабатывания.
- **Слово-активатор переключается в «Дом с Алисой»** («Алиса» или «Яндекс»). При выбранном
  «Яндекс» колонка на «Алиса» не просыпается — слово действительно освобождается.

## Где всё упирается

1. **Микрофон занят её процессом.** Настоящий микрофон — `hw:0,2` (`PDM-dummy`), его
   монопольно держит `maind --platformd`; второе открытие получает «занято». Свободные
   устройства записи (`hw:0,0`, `hw:0,1` — `tlv320adc3101`) отдают **цифровую тишину**:
   при громком звуке в комнате максимум амплитуды 88 из 32768. Отсюда главный вывод:
   «детектор ничего не слышит» почти всегда означает пустой вход, а не слабую модель.
2. **Потока микрофона в локальном канале нет.** В `127.0.0.1:9875` приходят кадры состояния
   (`253=3`), событий (`210`) и служебные (`207`); кадров звука `253=158` (канал `vqe_0`)
   нет ни в покое, ни во время её ответа. На Станции Мини 2 такой поток есть — на
   `yandexmidi` (Станция 2) его нет. Скрипт `mic-feed.c` повторяет их подписку
   (`{252:{1:""}, 253:159}`) один в один — и получает ноль кадров звука.
3. **Командная модель молчит.** `spotter_models/command` (слова `играй`, `дальше`, `стоп`,
   `пауза`, `продолжи`, `громче`, `тише` …) открывается и принимает кадры, но
   `spotter_get_next_event` не отдаёт ни одного события — вероятно, нужны дополнительные
   вызовы (`spotter_change_phrase_state` и родственные), назначение которых без
   документации не восстановлено. Прямой вызов `spotter_change_phrase_state` роняет процесс.
4. **Внедриться в её процесс нельзя.** Подмена библиотеки через `/etc/ld.so.preload`
   (`mic-tap.c`) приводит к тому, что `platformd` не стартует; второй экземпляр падает на
   занятом имени в системной шине (`sdbus … File exists`), а серия перезапусков однажды
   закончилась перезагрузкой колонки с видом «первая настройка».

## Файлы

| Файл | Что это |
|---|---|
| `zvuk-voice.c` | загрузка штатного споттера через `dlopen`, подача звука с микрофона |
| `vosk-kws.c` | офлайн-детектор слова на Vosk (движок и модель в репозиторий не входят) |
| `mic-feed.c` | подписка на звуковой поток её канала `9875` (на этой модели кадров нет) |
| `frames-dump.c` | печать структуры кадров канала: видно, какие сообщения вообще приходят |
| `mic-tap.c` | вставка в `platformd`, дублирующая прочитанный звук в канал (не сработала) |

## Вывод

Локальное распознавание на этой модели невозможно без доступа к микрофону, а его отдаёт
только процесс Алисы. Поэтому голос в плеере работает через её облачное распознавание
(две фразы, см. `docs/integration.md`), с известным ограничением: фразу слышит и она.
