# Как zvukd живёт рядом с AirPlay, Алисой и панелью

## Главное ограничение: одно ALSA-устройство

`dmix`/микшера на этом железе **нет** (проверено: одновременное владение
`pcmC0D0p` ломается). Значит в каждый момент звук держит ровно один процесс.
Сейчас арбитраж делает `audio-owner.sh`, который знает двух участников:
`shairport-sync` (AirPlay) и `maind --mediad` (Алиса). `zvukd` — третий.

## 1. Арбитраж: научить `audio-owner.sh` третьему участнику

Сейчас признак «идёт AirPlay» завязан на приёмник. Правильнее — на владение устройством.
Важно: у `zvukd` устройство держит не декодер, а вывод — `/usr/bin/aplay -q -f S16_LE
-r 44100 -c 2 -`; `mpg123` только пишет PCM в трубу. Проверка по `pcmC0D0p` его видит.

```sh
# кто-то, кроме mediad, держит pcmC0D0p → звук занят
busy() {
    for p in /proc/[0-9]*; do
        pid=${p#/proc/}
        [ "$pid" = "$$" ] && continue
        case "$(tr '\0' ' ' < "$p/cmdline" 2>/dev/null)" in
            *maind*mediad*) continue ;;
        esac
        ls -l "$p/fd" 2>/dev/null | grep -q 'pcmC0D0p' && return 0
    done
    return 1
}
```

Логика:

* `busy()` → `mediad` убить (Алиса молчит, это цена отсутствия микшера);
* не `busy()` дольше N секунд → перезапустить приёмник (отпускает устройство),
  затем поднять `mediad`.

Так `zvukd`, `shairport-sync` и Алиса не дерутся, и не нужно переписывать арбитраж
под каждый новый плеер.

## 2. Голос: `alice-voice.sh` → `zvukd` (сделано)

Слушатель ловит фразы из `/data/local/etc/voice-triggers.txt`, `hook()` превращает
совпадение в команду. Шаблоны в файле даны **без первой буквы** (сравнение побайтовое),
поэтому в `case` тоже «топ», «ыключи», «ауза», а не «стоп»/«выключи»/«пауза»:

```sh
hook() {
    phrase="$1"
    echo "$(date): СРАБОТАЛО «$phrase»" >> /data/local/tmp/alice-voice.log
    case "$phrase" in
        *трек*|*дальше*) CMD=next ;;
        *топ*|*ыключи*)  CMD=stop ;;
        *ауза*)          CMD=pause ;;
        *)               CMD=flow ;;   # «мой плеер», «музыка из звука»
    esac
    /data/local/bin/zvukd hush          # гасим саму Алису, ДО своего действия
    ( /data/local/bin/zvukd "$CMD" >> /data/local/tmp/zvukd.log 2>&1 & )
}
```

**`hush` обязателен и идёт первым.** Фразу слышит и облачная Алиса: она выполнит своё
намерение (включит свою музыку) и займёт ALSA — наш поток после этого умирает. `hush`
отправляет в её IPC отмену диалога (`AliceCapability`, метод 8) и паузу её плеера
(`PlaybackControlCapability`); формат кадров взят из `klockky/spotiya` и проверен
юнит-тестом по его же байтам. Отправка идёт напрямую, без демона плеера — важно успеть.

В фоне — только само действие: запуск потока качает трек несколько секунд, слушатель
ждать не должен.

Два известных момента:

* Алиса на «включи звук» может **убавить громкость** и начать свой ответ — поэтому
  триггеры подобраны без слова «громкость». Отмена её ответа — через IPC
  (`AliceCapability`), см. `docs/09-voice.md` в основном репозитории.
* Один и тот же распознанный текст приходит несколькими кадрами подряд — от повторного
  срабатывания спасает `COOLDOWN` и файл `/tmp/alice-voice.last`.

## 3. Панель: блок «Мой плеер» (сделано)

`panel-handler.sh` уже отдаёт JSON в `/api/status`; добавлены поля `zvuk`
(`play`/`pause`/`idle`/`off`) и `zvuk_title`. Пять действий — `/action?do=…`:
`zvuk-flow`, `zvuk-next`, `zvuk-pause`, `zvuk-resume`, `zvuk-stop`.

```sh
ZS=off; ZT="—"
ZOUT=$(/data/local/bin/zvukd status 2>/dev/null) || ZOUT=""
case "$ZOUT" in
  play\|*)  ZS=play;  ZT=$(printf '%s' "$ZOUT" | cut -d'|' -f2) ;;
  pause\|*) ZS=pause; ZT=$(printf '%s' "$ZOUT" | cut -d'|' -f2) ;;
  idle\|*)  ZS=idle ;;
esac
```

`zvuk-flow` и `zvuk-next` в обработчике запускаются в фоне: скачивание трека занимает
несколько секунд, и панель не должна столько ждать.

## 4. Подсветка

Кольцо уже умеет «горит, пока играет» — `led-lamp.sh` + `/run/led-lamp.stop`.
Проще всего не трогать `audio-owner.sh`, а дергать свет из `hook()`:

```sh
[ -x /data/local/bin/led-lamp.sh ] && /data/local/bin/led-lamp.sh tricolor &
```

и `touch /run/led-lamp.stop` на `stop`.

## 5. Что zvukd НЕ делает

* не показывает интерфейс — на колонке нет экрана, управление только командой/голосом/панелью;
* не декодирует звук сам — в режиме станции звук отдаёт её штатный плеер (`audio_play`),
  который играет и mp3, и FLAC; в режиме `ZVUK_MODE=alsa` — `mpg123`;
* не хранит музыку — играет по ссылке, кэша нет;
* не лезет в аккаунт дальше чтения (поиск + ссылка на поток).
